# 06 — IA

## Ponto de partida: o que o seu plano Pro permite

| Uso | Permitido com o plano Pro? |
|---|---|
| Conversar no claude.ai (web, desktop, celular) para estudar | Sim |
| Usar o Claude Code no terminal ou na IDE para construir este app | Sim |
| Usar o Claude Code para criar conteúdo do app no repositório (sementes, dicas, soluções de referência, textos das regras) | Sim: é uso normal do Claude Code, feito por você |
| O backend do app chamar o Claude com as credenciais do plano (OAuth, token de sessão, Claude Code ou Agent SDK rodando por baixo com o seu login) | **Não** |
| O backend do app chamar a Claude API com uma chave do Claude Console | Sim, mas é cobrado à parte (pré-pago, por uso) |

A página *Legal and compliance* da documentação do Claude Code diz, em resumo:

- a autenticação OAuth dos planos de assinatura (Free, Pro, Max…) existe para o uso normal do Claude Code e dos aplicativos nativos da Anthropic;
- desenvolvedores que constroem produtos ou serviços que interagem com o Claude, inclusive com o Agent SDK, devem usar autenticação por chave de API do Claude Console ou de um provedor de nuvem suportado;
- a Anthropic não permite rotear requisições pelas credenciais dos planos Free, Pro, Max ou Ultra, nem coletar ou intermediar credenciais e tokens de sessão do claude.ai, e pode aplicar essas restrições sem aviso.

Fonte: <https://code.claude.com/docs/en/legal-and-compliance> (consultada em 15/11/2026).

**Consequência de design:** o app precisa funcionar 100% sem IA em tempo de execução, e o plano Pro entra onde ele rende mais: na **autoria** do conteúdo.

## Estratégia em três camadas

| Camada | Quando roda | Quem faz | Custo |
|---|---|---|---|
| 1. Autoria | Enquanto você desenvolve e amplia a biblioteca, no terminal | Claude Code (plano Pro) + CLI `lab` para validar | Nenhum custo extra |
| 2. Execução determinística | Sempre | Motor + textos curados | Zero |
| 3. Execução com IA (opcional) | Se configurada | Ollama (local) ou Claude API | Zero (local) · pago (API) |

## Papéis da IA em cada modo

| Papel | `none` (sempre disponível) | `ollama` (local, grátis; o padrão na sua máquina) | `anthropic` (Claude API, opt-in) |
|---|---|---|---|
| Contexto → desafio | Busca na biblioteca + variação procedural | Personaliza uma semente (narrativa, variáveis, pegadinhas) | Personaliza uma semente, com mais liberdade narrativa |
| Entrevistador | Esclarecimentos curados + dicas curadas | Chat livre ancorado no desafio | Chat livre ancorado no desafio |
| Mapear forma não tipada | Aliases do catálogo | + sugestão do modelo | + sugestão do modelo |
| Sugerir fluxos | Busca no grafo | + ranking das alternativas | + ranking das alternativas |
| Revisão | Revisão determinística (05, Etapa 6) | + narrativa e follow-ups adaptados | + narrativa, follow-ups e comparação comentada com a referência |
| Nota | Determinística | Determinística | Determinística |

Em todos os modos, o que a IA produz passa pelas mesmas validações: JSON Schema, checagens semânticas e, para desafios, o motor executando a solução de referência.

## Camada 1 — Autoria com o Claude Code (a "fábrica de desafios")

```text
você ──▶ Claude Code, no repositório: "crie uma semente da trilha Cartões, nível Sênior,
         sobre autorização com stand-in"
           │
           ├─▶ escreve content/challenges/cartoes/autorizador-stand-in.yaml
           ├─▶ roda: lab challenge validate content/challenges/cartoes/autorizador-stand-in.yaml
           │     ◀── erros: schema, semântica, referência abaixo de 85, SLO impossível…
           └─▶ corrige e repete até passar
você ◀── revisa o diff e faz o commit
```

| Conteúdo | Arquivos | Validação |
|---|---|---|
| Sementes: enunciado, UCs, SLOs, workload, cenários, dicas, esclarecimentos, solução de referência, faixas de variação | `content/challenges/<trilha>/*.yaml` | `lab challenge validate`: schema + semântica + referência ≥ 85 nos cantos do espaço de variação |
| Textos das regras: por quê, como corrigir, trade-offs, follow-ups, links oficiais | `content/rules/*.yaml` | `lab rules validate`: toda regra tem texto; links só de domínios oficiais |
| Calibração do catálogo: limites, latências, preços com fonte e data | `content/catalog/**` | `lab catalog validate` |
| Arquiteturas quebradas do modo Plantão | `content/challenges/plantao/*.yaml` | A versão quebrada precisa falhar no cenário do incidente e a correção de referência precisa passar |

**Skills do Claude Code no repositório** (`.claude/skills/`):

- `novo-desafio`: schema, guia de estilo (pt-BR, realismo do mercado financeiro, números plausíveis), checklist e comando de validação.
- `calibrar-catalogo`: como consultar a documentação oficial dos provedores e registrar `source` e `reviewedAt`.
- `revisar-avaliacao`: lê um export (`lab export <tentativa>` gera `exports/<id>/{challenge,ir,evaluation}.json`) e escreve uma revisão aprofundada em markdown — uma segunda opinião, sob demanda, além da revisão determinística.

**Variação procedural.** Cada semente declara variáveis com faixas por dificuldade (ex.: `baselineRps: { pleno: [300, 800], senior: [1500, 4000] }`) e "pegadinhas" combináveis (conta quente, SPI degradado, auditoria obrigatória, orçamento apertado). Os parâmetros de capacidade da solução de referência podem usar expressões simples (ex.: `instances.min: "{{ ceil(baselineRps / 400) }}"`), avaliadas para cada variação. O validador roda a referência nos cantos do espaço de variação; se ela passa nos extremos, passa no meio.

**Limite claro:** o Claude Code é usado por você, de forma interativa, no seu terminal. O app nunca chama o Claude Code nem a sua assinatura (por exemplo, rodando `claude -p` a cada mensagem do chat): esse não é o caminho suportado para aplicações.

## Camada 2 — Execução determinística

- **Busca guiada:** FTS5 do SQLite sobre título, narrativa, tags e domínio das sementes, com filtros por provedor e dificuldade; cada resultado explica por que foi escolhido (tags que casaram). Sem contexto, o recomendador ([07](07-gamificacao.md)) decide.
- **Esclarecimentos curados:** cada semente traz `clarifications` (pergunta, palavras-chave, resposta). O painel do entrevistador mostra as perguntas frequentes do desafio e uma busca por palavra-chave, deixando claro que são respostas pré-definidas.
- **Dicas curadas** em 3 níveis, com custo de XP.
- **Revisão determinística:** ver [05, Etapa 6](05-motor-de-avaliacao.md#etapa-6--revisão).

## Camada 3 — Execução com IA (opcional)

### Portas e adaptadores


Cada porta tem três implementações: determinística (`none`), Ollama e Claude. A configuração escolhe o modo:

```jsonc
// appsettings.json
"Ai": {
  "Mode": "auto",              // auto | none | ollama | anthropic — auto = ollama se disponível, senão none
  "Ollama": { "Endpoint": "http://localhost:11434", "Model": "<definido no spike S4>" },
  "Anthropic": {
    "Enabled": false,          // opt-in explícito
    "Model": "<ID do modelo Opus atual, definido ao ligar o modo>",
    "MonthlyBudgetUsd": 0,     // precisa ser > 0 para ligar; bloqueia ao atingir
    "Effort": { "personalizer": "high", "interviewer": "low", "labelMapper": "low", "narrator": "medium" }
  }
}
```

A chave da Claude API, se um dia existir, fica em segredo local (`dotnet user-secrets` ou variável de ambiente `ANTHROPIC_API_KEY`) — nunca no repositório nem no frontend.

### A IA personaliza, não inventa

Em qualquer modo, a IA **não escreve o desafio inteiro**. Ela recebe a semente, as faixas permitidas e a lista de IDs válidos, e devolve um **delta pequeno** em JSON:

```json
{
  "seedId": "pix/envio-pix",
  "narrative": "A FinBank vai lançar PIX por aproximação em 3 meses…",
  "variables": { "baselineRps": 2200 },
  "twists": ["conta-quente"],
  "clarificationsExtra": [ { "q": "Existe limite noturno?", "a": "Sim, R$ 1.000 entre 20h e 6h." } ]
}
```

O desafio completo é montado de forma determinística a partir de semente + delta e passa pelo validador. Modelos locais pequenos acertam muito mais preenchendo um delta do que escrevendo um documento inteiro, e nada inválido chega à tela.

### Ollama (local, grátis)

- **Integração:** `IChatClient` do Microsoft.Extensions.AI, implementado pelo OllamaSharp; saída estruturada por JSON Schema (parâmetro `format` do Ollama).
- **Privacidade:** nada sai da sua máquina. Para quem trabalha no mercado financeiro, isso vale ouro.

**No seu notebook (16 GB de RAM, RTX 3050 Laptop com 4 GB de VRAM):**

| Classe de modelo (quantizado em 4 bits) | Cabe na GPU? | Experiência esperada | Uso no app |
|---|---|---|---|
| 3–4B parâmetros | Sim, inteiro, com contexto moderado | Rápida, conversa fluida | **Padrão:** entrevistador, narrativa, mapeamento de rótulos e personalização |
| 7–8B parâmetros | Não: o Ollama divide as camadas entre GPU e CPU | Várias vezes mais lenta | Referência de qualidade nos evals; opção para a personalização, que não é interativa |
| 14B ou mais | Não, e disputa os 16 GB de RAM com navegador, app e IDE | — | Fora |

- **Contexto curto:** o cache de atenção também ocupa VRAM, então `num_ctx` fica em torno de 8 mil tokens e os prompts levam só o necessário (parte pública do desafio, esclarecimentos relevantes, resumo dos achados).
- **Um modelo por vez**, com `keep_alive` de alguns minutos para não recarregar a cada mensagem.
- **Sem disputa com o motor:** o modelo roda na GPU; a simulação, na CPU.
- **JSON válido mesmo em modelo pequeno:** o Ollama transforma o JSON Schema numa gramática que restringe a geração; os evals medem a qualidade do conteúdo, não a sintaxe.
- **Escolha do modelo:** pelos evals do spike S4, entre as famílias abertas com versões de 3–4B e bom suporte a saída estruturada disponíveis no Ollama na época (ex.: Qwen, Gemma, Phi, Llama), mais um 7–8B como referência. Configurável a qualquer momento.
- **Entrevistador local:** recebe só a parte pública do desafio + os esclarecimentos curados. Não recebe a solução de referência nem os cenários ocultos — não dá para vazar o que ele não conhece. Dicas vêm do botão de dicas (curadas), não do modelo.

### Claude API (opt-in, pago)

Faz sentido se um dia você aceitar pagar por melhor conversa, personalização e narrativa.

**Estimativa de custo** (modelo Opus atual, preços de nov/2026: US$ 4 por milhão de tokens de entrada, US$ 20 de saída, US$ 0,20 de leitura de cache; o raciocínio conta como saída):

| Operação | Entrada | Saída | Custo estimado |
|---|---|---|---|
| Personalizar desafio (effort `high`) | ~10 mil tokens (8 mil em cache) | ~6 mil | ~US$ 0,13 |
| Turno do entrevistador (effort `low`) | ~8 mil (7 mil em cache) | ~600 | ~US$ 0,02 |
| Narrativa da revisão (effort `medium`) | ~15 mil (5 mil em cache) | ~5 mil | ~US$ 0,14 |
| Ciclo completo (1 desafio + 15 turnos + 2 revisões) | | | ~US$ 0,70 |
| Mês com 12 ciclos | | | **~US$ 9** |

Estimativas; o custo real vem do `usage` de cada resposta, registrado na tabela `ai_usage`.

**Configuração com a API atual:**

- SDK oficial `Anthropic` (NuGet), com o modelo Opus atual, lido da configuração (`Ai:Anthropic:Model`).
- `effort` em `output_config`, explícito por papel (neste modelo o padrão é `medium`). O raciocínio adaptativo está sempre ligado: não enviar `thinking: disabled` nem `budget_tokens` (a API devolve 400).
- Sem `temperature`/`top_p`/`top_k` (rejeitados). A consistência vem do schema, do delta pequeno e da ancoragem na revisão determinística.
- Sem prefill da resposta do assistente: o formato vem de saída estruturada (`output_config.format` com JSON Schema).
- `tool_choice` forçado (`any`/`tool`) devolve 400 neste modelo: usar `auto` + `strict: true` e instrução no prompt.
- Tratar `stop_reason: "refusal"` e habilitar o fallback no servidor (beta `server-side-fallback-2026-07-01`, `fallbacks: "default"`).
- Cache de prompt no prefixo estável (instruções, schema, semente, catálogo resumido); mínimo cacheável de 512 tokens neste modelo; TTL de 1 h no entrevistador, porque as perguntas são espaçadas enquanto você desenha; conferir `usage.cache_read_input_tokens`.
- Streaming no chat; Message Batches (50% mais barato) para trabalho sem pressa, como pré-personalizar desafios diários.
- O SDK emite spans OpenTelemetry (`com.anthropic.sdk.csharp*`).
- Teto mensal obrigatório: o custo de cada chamada é calculado a partir do `usage`; ao atingir o teto, o modo cai para `ollama` ou `none`.

Esboço do narrador, usando só membros documentados do SDK:

```csharp
using Anthropic;
using Anthropic.Models.Messages;

public sealed class ClaudeReviewNarrator(AnthropicClient client, PromptLibrary prompts, AiOptions options) : IReviewNarrator
{
    public async Task<ReviewNarrative> NarrateAsync(DeterministicReview review, CancellationToken ct)
    {
        var parameters = new MessageCreateParams
        {
            Model = options.Anthropic.Model,
            MaxTokens = 16000,
            OutputConfig = new OutputConfig
            {
                Effort = Effort.Medium,
                Format = new JsonOutputFormat { Schema = NarrativeSchema.Value }, // Dictionary<string, JsonElement>
            },
            System = new List<TextBlockParam>
            {
                new() { Text = prompts.Get("narrator", version: 2), CacheControl = new CacheControlEphemeral() },
            },
            Messages = [ new UserMessageParam { Content = review.ToPromptXml() } ],
        };

        var response = await client.Messages.Create(parameters);
        // 1. StopReason == "refusal" ou "max_tokens" → cai para a revisão determinística
        // 2. Extrair o TextBlock, desserializar e validar contra o schema
        // 3. Conferir elementos e números citados contra a revisão determinística
        ...
    }
}
```

### Ponte manual com o claude.ai (opcional, Fase 2)

Um botão "Personalizar com o claude.ai" copia um prompt pronto (semente + seu contexto + schema do delta). Você cola no claude.ai, copia o JSON da resposta e cola de volta no app, que valida como em qualquer outro modo. Qualidade do Claude, custo zero, dois cliques — e é você usando o claude.ai normalmente.

## Guardrails

- **Dados confidenciais:** nos modos `none` e `ollama`, nada sai da máquina. Quando algo vai sair (Claude API, ponte manual), o app mascara CPF/CNPJ, e-mails, telefones, IPs, hostnames internos, chaves de API e números de cartão (Luhn) e mostra quantos itens mascarou. Um aviso lembra de não colar informações do seu empregador.
- **Prompt injection:** contexto, rótulos e anotações entram delimitados como dados; a IA não tem poder sobre a nota; toda saída é validada.
- **Vazamento de spoilers:** o entrevistador nunca recebe a solução de referência nem os cenários ocultos.
- **Degradação:** se a IA falhar, demorar ou estourar o teto, a experiência cai para o modo `none` sem bloquear nada.

## Prompts versionados

`content/prompts/<papel>/v<n>.md`, com front-matter (modelos-alvo, schema, changelog). A versão usada fica no manifesto do desafio ou da avaliação.

## Evals

| Dataset | Tamanho | O que mede |
|---|---|---|
| Personalização | 20 contextos | % de deltas válidos na primeira tentativa; % aprovados no validador; aderência ao contexto (rubrica) |
| Entrevistador | 20 conversas roteirizadas | Não revela soluções; responde números do desafio corretamente; admite quando não sabe |
| Narrativa | 30 avaliações | Cita os 3 achados de maior impacto; não contradiz métricas; não inventa componentes |

Rodam no spike S4 (escolha do modelo local) e antes de trocar prompt ou modelo. No modo Claude API, o custo estimado aparece antes da execução.
